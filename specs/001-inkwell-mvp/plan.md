**Input**: Feature specification from `specs/001-inkwell-mvp/spec.md`

---

## Summary

Inkwell is a mobile-first PWA that captures handwritten journal pages via the browser camera, runs formatting-aware OCR through a Claude vision proxy, stores entries as structured Notion pages with auto-generated tags and topical relation links, and maintains a personalized on-device calibration profile that improves OCR accuracy over time. The MVP delivers all six spec user stories: camera capture, formatting OCR, calibration onboarding, Notion publishing, auto-tagging, and entry-to-entry relations.

---

## Technical Context

**Language/Version**: TypeScript 5.x (strict mode)
**Primary Dependencies**: React 19, Vite 6 + vite-plugin-pwa, Dexie.js v4, @notionhq/client, @vercel/blob, Tailwind CSS v4
**AI Provider**: Anthropic `claude-opus-4-6` vision via serverless proxy (`/api/ocr`, `/api/tag`, `/api/link-entries`)
**Storage**: IndexedDB (Dexie.js) for CalibrationProfile + PendingEntry; Notion API for all entry content; Vercel Blob for doodle image assets
**Testing**: Vitest + React Testing Library (unit/component); Playwright (E2E for auth + Notion publish flows)
**Target Platform**: PWA — iOS 16+ Safari, Android 12+ Chrome; desktop Chrome/Edge secondary
**Performance Goals**: Capture-to-publish < 90s end-to-end (SC-001); OCR response < 10s p95; Notion page creation < 3s p95
**Constraints**: HTTPS required (camera API); Notion API rate limit 3 req/s; image payload to OCR proxy ≤ 5MB; iOS Safari has no `ImageCapture` API (fallback to `<input capture>`)
**Scale/Scope**: Single-user, single-device MVP; Notion corpus up to ~200 entries before entry-linking optimization is needed; no concurrent users

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-checked post-design below.*

| Principle | Status | Evidence |
|---|---|---|
| I. Formatting Semantics Are the Product | ✅ PASS | OCR output contract has typed `formatting[]` and `doodles[]` with bounding boxes. `symbols[]` reserved (FR-028). Doodle crops embedded as Notion image blocks (not described as text). |
| II. Calibration is First-Class | ✅ PASS | `CalibrationProfile` is a named IndexedDB entity. Onboarding gated behind auth. Corrections feed back via `CalibrationHints` in OCR prompt. Stored on-device (IndexedDB), no server sync. |
| III. Notion is the Database | ✅ PASS | No proprietary content database. `PendingEntry` is temporary pre-publish state, deleted after successful publish. Doodle images in Vercel Blob are media assets (not entry content). Stateless proxy holds no user data. |
| IV. Every Entry Feeds the Knowledge Graph | ✅ PASS | Tagging and entry linking are synchronous steps in the publish flow — not background jobs. Failures surface to the user (FR-024 atomicity). |
| V. PWA-Only Distribution | ✅ PASS | Vite + vite-plugin-pwa. No native wrapper. Camera via `<input capture>` on iOS, `getUserMedia` on Android/desktop. Serverless functions are not a native layer. |
| VI. MVP Scope is Non-Negotiable | ✅ PASS | Tech stack covers exactly the 6 MVP capabilities. `symbols[]` is reserved but empty — zero implementation work for Editorial Marks Intelligence in this phase. |

**Post-design re-check**: All gates continue to pass. No violations requiring Complexity Tracking entries.

The frontend (`src/`) and serverless functions (`api/`) share TypeScript types via `src/types/index.ts`. The serverless functions are stateless proxies only — no database, no session storage.
