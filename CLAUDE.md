# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this project is

**Inkwell** — a PWA ("Where pen meets patterns") that bridges handwritten journaling with AI-powered knowledge mapping. Users photograph handwritten journal pages; the app performs formatting-aware OCR (capturing highlights, strikethroughs, spatial layout, and doodles — not just raw text), publishes structured entries to Notion, auto-tags them, and links related entries to build a personal knowledge graph over time.

## Spec Kit workflow

This project uses GitHub Spec Kit for spec-driven development. The Spec Kit integration lives entirely in `.specify/` and `.claude/skills/`. All commands are invoked as Claude skills.

**The core development loop**:

```
/speckit.constitution   → establish/amend project principles (.specify/memory/constitution.md)
/speckit.specify        → create feature spec (specs/NNN-feature-name/spec.md)
/speckit.clarify        → resolve spec ambiguities (interactive Q&A, updates spec in place)
/speckit.plan           → generate implementation plan, research, data model, contracts
/speckit.tasks          → generate tasks.md from plan artifacts
/speckit.analyze        → cross-artifact consistency check (read-only)
/speckit.checklist      → generate requirements quality checklists
/speckit.implement      → execute tasks from tasks.md
/speckit.taskstoissues  → sync tasks.md to GitHub issues
```

**Git hooks run automatically** around each command (branch creation before `/speckit.specify`, optional auto-commits after each step). Hook config: `.specify/extensions.yml`.

**Active feature directory** is tracked in `.specify/feature.json`. All `plan`, `tasks`, `analyze`, `implement` commands read this to locate the current feature's artifacts.

**Feature artifacts** live at `specs/NNN-feature-name/`:

## Constitution (non-negotiable principles)

Full text: `.specify/memory/constitution.md`. Summary:

1. **Formatting semantics are the product** — OCR MUST capture highlights, strikethroughs, spatial structure, and doodle bounding regions as structured fields. Raw-text-only output is incomplete.
2. **Calibration is first-class** — Distinct named UX, not a background process. 3–5 onboarding samples required. Post-capture corrections feed back into the model. Stored on-device (IndexedDB) — no server sync in MVP.
3. **Notion is the database** — No proprietary storage layer. All entry content, tags, and relations live in Notion as native blocks, properties, and page relations.
4. **Every entry feeds the knowledge graph** — Auto-tagging and entry-to-entry relation linking MUST happen atomically on each publish. Not deferred to a background job.
5. **PWA-only** — `MediaDevices.getUserMedia()` for camera. No native wrappers (React Native, Capacitor, Cordova). Installable via browser "Add to Home Screen."
6. **MVP scope is fixed** — Photo capture, formatting OCR, calibration onboarding, Notion page creation, auto-tagging, entry relations. Everything else (digests, graph UI, Obsidian, multi-user) is deferred until corpus exists.

Every plan and task breakdown requires a Constitution Check section validating against all six principles.

## Tech stack (decided in plan)

- **Frontend**: React 19 + TypeScript 5 + Vite 6 + `vite-plugin-pwa` + Tailwind CSS v4
- **Serverless proxy**: Vercel Edge Functions (`api/`) — stateless, holds API keys only
- **AI**: Anthropic `claude-opus-4-6` vision for OCR, tag extraction, and entry linking
- **On-device storage**: Dexie.js v4 (IndexedDB) — CalibrationProfile, PendingEntry, NotionAuthToken
- **Doodle image hosting**: Vercel Blob (public, no expiry) — doodle crops only, not entry content
- **Camera**: `<input type="file" capture="environment">` on iOS; `MediaDevices.getUserMedia()` on Android/desktop
- **Testing**: Vitest + React Testing Library (unit); Playwright (E2E)

## Key decisions already made

- **Calibration persistence**: IndexedDB, on-device only. Cross-device sync is v2.
- **Doodle representation in Notion**: Cropped image regions as Notion image blocks. OCR output includes bounding coordinates per doodle region.
- **`symbols` array in OCR output**: Reserved top-level field, always `[]` for MVP (FR-028). For Editorial Marks Intelligence post-MVP. Do not remove or rename.
- **No direct browser-to-AI calls**: All Anthropic API calls go through stateless Vercel Edge Functions that hold the API key. Notion API calls after OAuth are made directly from the browser.
- **Entry linking**: Claude prompt-based similarity (fetch last 50 Notion page titles/tags, ask Claude to identify related ones). Switchable to embeddings post-MVP at ~500 entries.
- **Notion OAuth**: Standard auth code flow; `client_secret` exchange happens server-side in `/api/auth/callback`; token returned in URL hash, stored in IndexedDB.
